# Contributing

Thanks for helping improve Awesome AI for Science.

## What belongs here

A project should:

- make scientific research or scientific engineering a primary use case;
- provide runnable source code, not only a paper, landing page, or product announcement;
- have enough documentation for another person to understand its scope and try it;
- clearly identify its current maturity and important limitations; and
- fit one of the existing sections, or justify a new section with several relevant projects.

Projects may be early-stage. Their descriptions must distinguish working features from roadmap claims.

## Before opening a pull request

1. Search the list and open pull requests for duplicates.
2. Verify the repository URL, current project name, interfaces, supported platforms, and license.
3. Read the upstream README and describe only capabilities it currently claims to provide.
4. Add the project to both `README.md` and `README.zh-CN.md`.
5. Keep entries concise, factual, and free of rankings or promotional language.

Use this format:

```markdown
- **[Project name](https://github.com/owner/repository)** — One or two factual sentences explaining what it is, how it is used, and what distinguishes it. `Primary language` `License`
```

## Pull request rules

- Submit one project per pull request.
- Explain why it belongs in the list.
- Disclose whether you are an owner, maintainer, employee, investor, or otherwise affiliated with the project.
- Do not use referral, tracking, or URL-shortener links.
- Do not copy marketing claims that cannot be checked in the repository.
- Keep the comparison table and detailed entry consistent.

Maintainers may edit descriptions for clarity and consistency, move entries between sections, or remove abandoned, unavailable, malicious, or no-longer-relevant projects.
